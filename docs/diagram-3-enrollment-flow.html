PUFShield — PUF + PKI Enrollment & Authentication

Flow A runs once per device at onboarding · Flow B runs at every boot
FLOW A — DEVICE ENROLLMENT
1
New Device Registration
device_id generated and persisted
2
SRAM PUF Sampling
10 captures → multi-capture baseline
3
PUF Stability Analysis
BER, Hamming distance, stable-bit selection
4
BCH Fuzzy Extraction
BCH(31,16,7) → helper data + stable reference
5
HKDF-SHA256 Key Derivation
Domain-separated keys: device-auth, firmware-encryption, boot-integrity
6
Server Credential Generation
HMAC-SHA256(server_secret, device-auth key) · secret stored in data/puf_secret.bin
7
ECDSA P-256 Key Pair Generation
Device private + public key generated on-device
8
X.509 Certificate Issuance
CA signs device cert (ECDSA P-256, SHA-256)
9
PUF-PKI Binding
binding_hash = HKDF(puf_secret ‖ DER_spki)
10
Enrollment Storage
SQLite: devices, puf_enrollments, certificates tables
FLOW B — BOOT-TIME AUTHENTICATION
1
Power On → PUF Measurement
Raw SRAM response read at boot
2
PUF Reconstruction
BCH decode + credential match
3
PUF-PKI Binding Verification
Recompute binding hash and compare
4
Certificate Chain Validation
RFC 5280 full chain to trusted root
5
Challenge Generation
32-byte nonce, TTL 60s
6
Device Signs Challenge
ECDSA P-256 over "pufshield-auth:v1:{id}:{nonce}"
7
Server Verifies
Signature + cert chain + PUF binding
8
Atomic Nonce Consumption
Single-use enforcement — replay prevention
9
Auth Result
Pass/fail decision + audit log entry
Enrollment establishes the hardware-rooted identity (once) · Boot-time authentication proves it (every boot) — both anchored in the same physical PUF.
