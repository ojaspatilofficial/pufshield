PUFShield — Attack Detection Flows

Six attack classes mapped to the exact pipeline stages that neutralize them
All attacks flow through the ACTUAL 11-stage boot pipeline — they are not simulated independently. Each attack is caught at a specific, real pipeline stage.
01DEVICE CLONING
ATTACKCopy certificate + public key + firmware to a different device
DETECTPUF-PKI Binding Mismatch (Stage 3) — different silicon → different PUF → different binding hash
CHAINOriginal PUF ≠ Cloned PUF → binding_hash mismatch
RESULTBOOT BLOCKED
02FIRMWARE TAMPERING
ATTACKModify firmware binary while keeping original signatures
DETECTSHA-256 Hash Mismatch (Stage 6) — modified binary produces a different digest than the signed manifest
RESULTBOOT BLOCKED
03REPLAY ATTACK
ATTACKReuse a previously captured authentication response
DETECTNonce Already Consumed (Stage 5) — atomic consumption makes every nonce single-use
RESULTAUTHENTICATION BLOCKED
04CERTIFICATE FORGERY
ATTACKCreate fake certificate with rogue CA, inject into key store
DETECTX.509 Chain Validation Failure (Stage 4) — rogue CA absent from trust chain (RFC 5280)
RESULTAUTHENTICATION BLOCKED
05FIRMWARE ROLLBACK
ATTACKDeploy older, validly-signed firmware to exploit known vulnerabilities
DETECTAnti-Rollback Version Policy (Stage 8) — strict dotted-version < minimum allowed
RESULTBOOT BLOCKED
06WRONG SIGNER
ATTACKSign firmware with unauthorized key instead of manufacturer key
DETECTManufacturer Signature Verification Failure (Stage 7) — dual-signature scheme requires device + manufacturer keys
RESULTBOOT BLOCKED
